# hyprmoncfg 1.23.0

A reliability release. Your display layout is no longer rebuilt when hyprmoncfg first meets a desk it already works on, a rejected layout stops flipping your screens back and forth, and waking the displays no longer makes the lock screen wait for a Hyprland reload. Install from the AUR or download a package below. Pair it with [panel 2.8.0](https://github.com/crmne/omarchy-hyprmoncfg/releases/tag/v2.8.0) for Omarchy.

## New

- **A working desk is kept as it is** ([#77](https://github.com/crmne/hyprmoncfg/pull/77)). With no saved profile for the connected displays, the daemon used to rebuild the layout from scratch: it could pick an advertised 4096x2160 mode for a TV running 3840x2160 and drop a portrait display's rotation. It now keeps the resolution, position and rotation of displays that already show a picture, and their workspaces. Displays that are off or have no mode are still placed to the right as before. By @keylimesoda.
- **A rejected layout stops retrying.** If an automatic apply fails its check and rolls back to displays that work, the daemon now pauses that same request instead of switching back and forth. Editing the profile, a display or workspace change, `hyprmoncfg manage`, turning automatic selection on, or keeping a preview tries again. A failed rollback, and displays that came back without a mode, keep retrying as before. The pause lasts until the daemon restarts and is logged as `automatic retry paused`.

## Fixed

- **The lock screen takes your password as soon as the displays wake** ([#86](https://github.com/crmne/hyprmoncfg/issues/86)). After a wake, the daemon applies the active profile again, and each apply rewrote the generated monitor file and reloaded Hyprland, even when nothing had changed. The lock screen waited for that reload, about 12 seconds in the report, and binds added at runtime were lost. When the file would come out identical and the displays already match, hyprmoncfg now skips the write and the reload. Reported by @linuskelsey.
- **No more endless reconciliations after a display change** ([omarchy-hyprmoncfg#31](https://github.com/crmne/omarchy-hyprmoncfg/issues/31)). With monitor management off, or a gently woken display missing from the profile, the timer that switches that display to its saved settings re-armed after every pass: thousands of passes a minute, each querying Hyprland, until the daemon was restarted. It now fires once per connection. Reported by @aishag80g-stack.
- **The laptop panel brings a dark external display back with the lid closed** ([#67](https://github.com/crmne/hyprmoncfg/issues/67)). Since 1.21.0 the daemon turns the built-in panel on when no external shows a picture, because some drivers only give an external its mode back once another output is lit. On an Intel laptop with the lid closed, the reload turned the panel on without a mode, which lit nothing, and the daemon counted it as done. It now sets the panel's mode directly when that happens, and only counts the apply once the panel has one. Reported and diagnosed by @itsDamon.
- **Changing one display's scale or mode no longer moves unrelated displays** ([#89](https://github.com/crmne/hyprmoncfg/pull/89)). Shrinking a display shifted every display past its old right or bottom edge, even in another row, and could push a laptop panel into a monitor and refuse the edit. Only displays attached to the resized one now move. This applies in the TUI and the panel. By @mrlarsendk.
- **A custom `--monitors-conf` file gets one include.** A generated file whose name doesn't contain "hyprmoncfg" gained another `source` line in the root config on every apply, which also forced a reload each time, and handing configuration back left those lines behind.
- **A verification failure is reported as one,** even when a later read times out. It used to look like a busy compositor.

## Known limitations

- **The live layout kept on a new desk uses VRR off and 8-bit colour,** as new layouts always have. Hyprland reports what those are doing right now, not how they were configured, so copying them would turn momentary activity into settings.
- **A display set up outside hyprmoncfg that Hyprland already turned on** keeps Hyprland's own mode and position when no profile matches, instead of being placed to the right at its best mode.

## Upgrading

Update both `hyprmoncfg` and `hyprmoncfgd`, then restart the service:

```sh
systemctl --user restart hyprmoncfgd.service
```

The IPC protocol is still version 1.

## What's tested

- **Automated tests** cover each fix with a fake compositor, fake clock or temporary files: the settle timer with management off, skipped and required reloads for `.conf` and Lua configs, the panel rescue with and without a mode coming back, the layout kept on a new desk, the retry pause and what lifts it, and the reflow cases from #89, including a randomized property test.
- **On real hardware:** @keylimesoda checked the layout kept on a new desk on their two-display desktop with a portrait display.
- **Not tried on the reporters' hardware:** the lock-screen timing (#86), the reconciliation loop on NVIDIA (omarchy-hyprmoncfg#31) and the Intel lid-closed rescue (#67). Feedback on those issues is very welcome.
